# 异常接口用例设计（16 组）

> 设计 16 组覆盖事务、幂等、状态流转、参数边界的异常接口用例。
> 分四组各 4 组用例，每组标注了验证方式（单测 / 接口请求）与预期结果。

## 一、事务组（多表写入一致性，4 组）

| # | 用例 | 验证方式 | 预期 |
|---|------|---------|------|
| T1 | 新增商品时喜好数据非法导致 `dish_flavor` 插入失败 | 单测/构造脏数据 | `@Transactional` 回滚，`dish` 表无残留记录 |
| T2 | 修改组合套装时明细插入失败 | 构造超长字段 | 组合套装主表更新回滚，明细表无孤儿记录 |
| T3 | 下单过程中清空购物车校验失败（购物车条目被并发删除） | 接口：提交不存在的 cartItemIds | 返回「购物车为空」，orders/order_detail 均不产生数据 |
| T4 | 下单成功后购物车对应条目必须被清除 | 接口：下单后 GET /user/shoppingCart/list | 已下单条目从购物车消失 |

## 二、幂等组（重复提交防护，4 组）

| # | 用例 | 验证方式 | 预期 |
|---|------|---------|------|
| I1 | 5 秒内同一用户重复提交下单请求 | 接口：连续两次 POST /user/order/submit | 第二次返回「订单提交中，请勿重复点击」 |
| I2 | 锁释放后正常重新下单 | 接口：等待 5 秒后重试 | 正常生成新订单 |
| I3 | 对同一订单号重复执行支付 | 接口：对已支付订单再次 PUT /user/order/payment/{number} | 状态机拦截：待发货不允许 PAY，返回非法流转错误 |
| I4 | 不同用户并发下单互不阻塞（幂等锁按用户隔离） | JMeter 多用户并发 | 各自正常下单，无「重复提交」误报 |

## 三、状态流转组（状态机约束，4 组）

| # | 用例 | 验证方式 | 预期 |
|---|------|---------|------|
| S1 | 待收货订单执行取消 | 接口：PUT /user/order/cancel/{id} | 返回「非法订单状态流转」，状态保持待收货 |
| S2 | 配送中订单执行取消订单 | 接口：PUT /admin/order/reject/{id} | 状态机拦截，状态不变 |
| S3 | 已完成订单重复完成 | 接口：PUT /admin/order/complete/{id} | 状态机拦截，返回非法流转错误 |
| S4 | 全链路正向流转：下单→支付→发货→配送→完成 | 接口：按序调用 | 每步状态 1→2→3→4→5 均成功 |

## 四、参数边界组（4 组）

| # | 用例 | 验证方式 | 预期 |
|---|------|---------|------|
| P1 | 下单缺收货人/电话/地址 | 接口：POST /user/order/submit 空 consignee | `@Valid` 校验失败，返回「收货人不能为空」 |
| P2 | 下单 cartItemIds 为空列表 | 接口：POST /user/order/submit cartItemIds=[] | 返回「购物车不能为空」 |
| P3 | 用户 A 操作用户 B 的订单（取消/查详情） | 接口：携带 A 的 token 操作 B 的订单 | 返回「无权限操作该订单」 |
| P4 | 无 token / 篡改 token 访问鉴权接口 | 接口：不带 token 或伪造 token | HTTP 401，返回登录失败 |

## 运行方式

- 单测部分（状态机 14 个断言 + JWT 4 个 + 密码 3 个）：`mvn test`
- 接口部分：按 README 启动应用后，用 Apifox/Postman 按上表逐条执行
